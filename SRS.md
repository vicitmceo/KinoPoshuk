## 1. Вступ

### 1.1 Мета документа

Цей документ є єдиним джерелом правди щодо функціональних та нефункціональних
вимог до веб-застосунку "Кінопошук" на етапі курсового проєкту. Документ
використовується для затвердження теми проєкту викладачем та як базис для
планування розробки за методологією Scrum.

### 1.2 Область застосування продукту

"Кінопошук" — веб-застосунок для пошуку інформації про фільми за назвою.
Користувач вводить назву фільму, застосунок звертається до зовнішнього OMDb API
і відображає картку фільму: постер, рік випуску, режисера, акторський склад,
жанр, тривалість, рейтинг та короткий опис сюжету.

### 1.3 Терміни та скорочення

| Термін | Опис |
|---|---|
| OMDb API | Open Movie Database — публічне REST API з даними про фільми |
| SRS | Software Requirements Specification |
| SPA-подібний UI | Односторінковий інтерфейс без перезавантаження сторінки |
| MVP | Minimum Viable Product |

## 2. Загальний опис

### 2.1 Архітектурна перспектива

Застосунок побудований за архітектурою "тонкий клієнт — бекенд-проксі — зовнішнє API":

- **Frontend:** статичні HTML/CSS/JS файли (`wwwroot/`), без фреймворків
- **Backend:** ASP.NET Core Minimal API (.NET 9), проксіює запити до OMDb API
  та приховує API-ключ від клієнта
- **Зовнішній сервіс:** OMDb API — джерело даних про фільми

### 2.2 Класи користувачів

| Клас | Опис |
|---|---|
| Відвідувач | Будь-який користувач без реєстрації, може шукати фільми |

Реєстрація та розмежування прав у поточній версії (MVP) не передбачені.

### 2.3 Технічне середовище

- Backend: ASP.NET Core 9 (Minimal API)
- Frontend: HTML5, CSS3, Vanilla JavaScript (Fetch API)
- Розгортання: локально (`dotnet run`) або хостинг ASP.NET Core сумісний з провайдером
- Підтримувані браузери: останні версії Chrome, Firefox, Edge

### 2.4 Технологічні обмеження

- Ліміт запитів OMDb API для безкоштовного ключа (1000 запитів/день)
- API-ключ зберігається лише на бекенді, не передається клієнту
- Без бази даних на MVP-етапі — усі дані запитуються "на льоту" з OMDb

## 3. Межі проєкту

### In Scope (MVP)

- Пошук фільму за точною або частковою назвою
- Відображення картки фільму з постером і метаданими
- Обробка помилок (фільм не знайдено, порожній запит, недоступність API)
- Адаптивний стилізований інтерфейс

### Out of Scope (поточна ітерація)

- Реєстрація/авторизація користувачів
- Збереження історії пошуку чи "обраного" у БД
- Рекомендаційна система
- Мультимовність інтерфейсу (крім української)
- Власна база даних фільмів (незалежна від OMDb)

## 4. Функціональні вимоги

| ID | Вимога | Пріоритет (MoSCoW) | Критерій прийняття |
|---|---|---|---|
| FR-1 | Користувач вводить назву фільму в поле пошуку | Must | Поле вводу присутнє на головній сторінці |
| FR-2 | При натисканні "Пошук" застосунок надсилає запит на `/api/search?title=...` | Must | Запит виконується без перезавантаження сторінки |
| FR-3 | Бекенд проксіює запит до OMDb API з прихованим ключем | Must | Ключ API відсутній у клієнтському коді/мережевих запитах браузера |
| FR-4 | Результат відображається карткою: постер, назва, рік, режисер, актори, жанр, рейтинг, опис | Must | Усі поля видимі при успішному пошуку |
| FR-5 | Якщо фільм не знайдено — показується повідомлення про помилку | Must | Текст "Фільм не знайдено" при відповіді OMDb `Response: False` |
| FR-6 | Порожній запит блокується на клієнті | Should | Кнопка "Пошук" не надсилає запит при порожньому полі |
| FR-7 | Пошук за натисканням Enter | Could | Поле вводу реагує на клавішу Enter так само, як кнопка |

## 5. Use Cases

### UC-1: Успішний пошук фільму

1. Користувач відкриває головну сторінку
2. Вводить назву фільму (напр. "Inception")
3. Натискає "Пошук"
4. Застосунок показує індикатор завантаження
5. Бекенд отримує дані з OMDb і повертає JSON
6. Frontend рендерить картку фільму

**Постумова:** картка фільму відображена, поле пошуку не очищується

### UC-2: Фільм не знайдено

1. Користувач вводить назву неіснуючого фільму
2. Бекенд отримує від OMDb `{"Response":"False","Error":"Movie not found!"}`
3. Frontend показує повідомлення "Фільм не знайдено"

### UC-3: Недоступність OMDb API

1. Користувач виконує пошук під час недоступності зовнішнього API
2. Бекенд отримує помилку мережі/таймаут
3. Frontend показує повідомлення "Сервіс тимчасово недоступний, спробуйте пізніше"

## 6. Нефункціональні вимоги

| Категорія | Вимога |
|---|---|
| Продуктивність | Відповідь на пошуковий запит — не довше 3 секунд за нормальних умов мережі |
| Надійність | Коректна обробка помилок зовнішнього API без падіння застосунку |
| Безпека | API-ключ OMDb не потрапляє у відповідь клієнту та в репозиторій у відкритому вигляді (винести в конфігурацію / user-secrets на наступних ітераціях) |
| Юзабіліті | Інтерфейс українською мовою, зрозумілий без інструкцій |
| Доступність | Достатній контраст кольорів, читабельна типографіка |

## 7. Ризики

| Ризик | Імовірність | Вплив | Мітигація |
|---|---|---|---|
| Вичерпання денного ліміту OMDb API | Середня | Середній | Кешування останніх запитів, повідомлення користувачу |
| Зміна структури відповіді OMDb API | Низька | Високий | Валідація полів на бекенді перед відправкою клієнту |
| Відсутність БД ускладнює розширення функціоналу | Висока (на MVP) | Середній | Заплановано перехід на власну БД (SQL Server) у наступній ітерації |

---

## 8. Метрики успіху MVP

- Успішний пошук ≥ 95% валідних назв фільмів, наявних в OMDb
- Час відповіді інтерфейсу ≤ 3 сек
- Коректна обробка 100% помилкових сценаріїв (порожній запит, фільм не знайдено, недоступність API)

---

## 9. План розвитку після MVP

1. Перенесення історії пошуків та "обраного" у власну БД (SQL Server + EF Core)
2. Кешування відповідей OMDb для зменшення кількості зовнішніх запитів
3. Пагінація та розширений пошук (за роком, жанром)
4. Адаптивна верстка під мобільні пристрої
